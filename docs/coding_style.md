# 自维护代码规范

## 1. 适用范围与参考

适用于 `User/`、`templates/` 的自维护 C/H、获批 USER CODE 区域内新增的自维护代码，
以及本工程自维护文档和工具。禁止为了统一风格而修改 `.ioc`、USER CODE 区域外的生成代码、
厂商驱动或参考工程。不得对生成文件做整文件格式化或转码；标记行和区域外内容逐字节保留。
新增片段使用 UTF-8 无 BOM、LF，不统一改写生成文件已有内容的行尾或排版。
现有检查工具仍排除 `Core/`，其中新增片段需单独审阅，不能用受管文本检查代替固件编译。

注释风格参考用户指定的 `Taurus-arm/user/Kinematics`：中文 Doxygen、模块分区、参数物理意义、
算法原理、使用约束和验证依据。该参考目录使用 GB2312；本工程不沿用其编码，也不复制其中
混合命名、Tab、旧兼容宏或与超电无关的接口。
控制语句布局另参考用户指定的 `Taurus-arm/user/task/arm_task.c`，按下述统一约定书写。
本文是独立规范，接手时无需访问参考目录。

## 2. 编码与排版

- 自维护文本统一 **UTF-8 无 BOM、LF**，文件结尾保留换行，不保留行末空格。
- C/H 用 4 空格缩进，不用 Tab。建议行宽 100；必要的公式、路径和链接可超过。
- 保留的函数、结构体、枚举、条件和循环大括号采用 Allman 风格，另起一行。
  `case/default` 的右大括号与 `break;` 同行是明确例外，见下方示例。
- `if`、`else if`、`for`、`while`、`switch` 与左括号之间不留空格；函数调用同样不留空格。
  `else if` 两个关键字之间保留一个空格。
- `if/else` 分支只有一条简单语句时允许省略大括号，语句必须另起一行并缩进一级。
  多条语句或嵌套条件使用大括号，避免悬空 else；单语句也可以保留大括号。
- `else` 独立一行；不同分支不堆到同一行。其他控制语句保留大括号。
- 运算符两侧、逗号后、`for` 分号后保留一个空格，分支之间空一行。
- 指针写作 `Module_t *module`、`const Module_t *module`；一条声明只定义一个变量。
- 使用 `/* ==================== 公共接口 ==================== */` 等分区，按实际内容设置，
  不堆积空分区。实现文件顺序为文件说明、包含、私有定义、私有声明、公共实现、私有实现。
- `.c` 优先包含自己的头文件；其他依赖按项目/平台、标准库分组，只包含实际需要的头文件。
  纯算法不包含 `main.h` 或 HAL；不创建汇集全工程头文件的万能依赖。

正确：

```c
if(module == NULL)
    return MODULE_RESULT_INVALID_PARAM;

if(module->state == MODULE_STATE_UNINITIALIZED)
{
    ModuleResult_e result = Module_Init(module);
    return result;
}
else if(module->state == MODULE_STATE_READY)
    return MODULE_RESULT_OK;
else
    return MODULE_RESULT_INVALID_PARAM;
```

不采用：

```c
if(module==NULL) return -1;
```

`switch` 使用以下布局：`case/default` 相对 `switch` 缩进一级，每个分支有独立作用域；
分支右大括号后固定 **四个普通空格** 再写 `break;`，不使用 Tab。分支内容再缩进一级。
以 `return` 等方式直接离开函数的分支不需要不可达的 `break`；普通结束分支使用下方写法。

```c
// clang-format off
switch(module->state)
{
    case MODULE_STATE_UNINITIALIZED:
    {
        result = Module_Init(module);
    }    break;

    case MODULE_STATE_READY:
    {
        // 保持原有就绪状态。
    }    break;

    default:
    {
        result = MODULE_RESULT_INVALID_PARAM;
    }    break;
}
// clang-format on
```

循环书写为 `for(uint32_t i = 0U; i < sample_count; i++)`、`while(remaining_count > 0U)`，
循环体大括号另起一行。完整示例见 `templates/module_template.c` 文件末尾 Doxygen `@code` 区。
这些示例不参与模板编译，也不增加固件接口。

`.clang-format` 负责其可表达的机械排版；单语句仍保持另起一行，不自动增删已选定的大括号。
原生配置无法表达 `}    break;`，真实代码的上述 `switch` 须用独立的
`// clang-format off` / `// clang-format on` 注释保护，再人工检查其中的布局。
模板注释示例由 `ReflowComments: false` 保留。
工具不能判断名称、单位、架构、空指针策略或注释是否真实。
只有在修改清单明确列出文件并获批后才能写回排版；默认仅运行只读检查。

## 3. 名称与大小写

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| C/H 文件 | 小写下划线，配对文件同名 | `power_ctrl.c` / `power_ctrl.h` |
| 模块前缀 | 有语义的 PascalCase，统一缩写拼法 | `PowerCtrl`、`BspAdc`、`Pid` |
| 公共及私有函数 | `Module_VerbObject`，私有函数加 `static` | `PowerCtrl_Init()`、`BspAdc_ReadVoltage()` |
| 结构体类型 | PascalCase 加 `_t` | `PowerCtrl_t` |
| 枚举类型 | PascalCase 加 `_e` | `PowerCtrlState_e` |
| 枚举成员、宏 | 模块前缀加大写下划线 | `POWER_CTRL_STATE_IDLE` |
| 参数、局部变量、结构体成员 | 小写下划线 | `input_voltage_v`、`sample_count` |
| 文件私有变量 | `static` 加 `s_` | `s_power_ctrl` |
| 必要的跨文件全局变量 | `g_`，在唯一 C 文件定义 | `g_system_status` |
| 头文件保护 | `SUPERPOWER_` 加模块名和 `_H` | `SUPERPOWER_POWER_CTRL_H` |

宏和枚举成员使用公共命名空间，必须带模块前缀。不使用 `__XXX_H__` 等保留名称。
只读数据使用 `const`；文件私有对象仍遵守 `s_`，宏常量使用大写。不要为常量引入另一套命名。
`is_`、`has_`、`can_` 可用于布尔含义；循环索引可用 `i`，业务量避免 `temp1`、`data2` 等模糊名。
不使用拼音或无意义的类型前缀；数学推导中的短变量可以保留，但必须解释含义。

硬件及外部接口的既有名称按原接口保留，例如 `HAL_ADC_Start_DMA()` 和协议字段；
不能为了命名统一去改厂商声明、生成符号或线上协议。

## 4. 单位、数值与接口

- 物理量在变量名中携带单位后缀，例如 `_v`、`_mv`、`_a`、`_ma`、`_w`、`_j`、`_ms`、
  `_us`、`_hz`、`_percent`；宏使用相应大写后缀。同一计算链明确转换位置。
- 不从旧工程猜测采样比例、保护阈值、控制周期、方向或 CAN 帧定义。实际参数须有来源和验证状态。
- 计数、协议和位宽明确的数据使用 `<stdint.h>` 的定宽整数；布尔使用 `<stdbool.h>` 的 `bool`。
- 使用 `float` 运算时为对应常量加 `f`；是否需要 `double` 由精度需求与目标性能决定。
- 不在头文件中定义可变全局对象；优先通过实例和接口交互，不暴露内部状态供跨模块任意修改。
- 输入只读时使用 `const`。数组接口说明长度、容量、所有权和生命周期。
- 错误使用具名枚举或已约定的返回类型；不能把错误和有效测量值混用。
- 指针参数的可空性、未初始化行为、错误时输出是否有效，必须写明并与实现一致。
- 不默认使用 `volatile` 解决并发；中断共享、原子性、临界区和数据一致性需单独设计。
- 结构体紧凑布局仅在协议/存储格式确有要求时使用，并说明对齐和端序，不全局套用 `pack(1)`。
- 普通函数式宏须加括号并避免重复求值副作用；优先使用清晰的类型化函数。

## 5. 中文 Doxygen 注释

### 文件与公共接口

文件头至少包含 `@file`、`@brief`。模块复杂时用 `@details` 说明功能、依赖和处理流程，
用 `@note` 描述调用上下文、并发边界及硬件限制。不虚构作者、日期、出处或验证历史。

公共函数在头文件完整说明契约，使用 `@param[in]`、`@param[out]`、`@param[in,out]`、
`@return` 或 `@retval`。只填写适用信息，不为 `void` 函数编造返回值。
源文件不重复整段接口注释；说明实现原理、公式、取舍和局部限制。

结构体成员可用 `/**< 含义、单位与范围 */`，枚举成员说明状态或错误意义。
参数注释写清“什么量”，不能只重复参数名。

说明性示例，非已实现接口或实际硬件阈值：

```c
/**
 * @brief 将电压采样值转换为物理量。
 * @param[in] raw_count ADC 原始计数，有效范围由已确认的采样分辨率决定。
 * @param[out] voltage_v 换算电压，单位 V；必须指向有效可写对象。
 * @return 返回值约定见接口所属模块的结果枚举。
 * @note 换算比例必须来自当前板卡的已确认参数，错误时输出有效性需在正式接口中定义。
 */
```

正式代码不能保留上述说明性示例中的未决契约；参数未确认时先记录问题，不假装完成实现。
完整、可独立编译的注释与接口示例见 `templates/module_template.h`。

### 原理、边界与验证

- 对控制公式说明变量、单位、离散周期、限幅和异常处理，不仅贴出一个公式。
- 对标定参数说明测量/计算来源、适用板卡及确认状态。
- 对中断调用说明上下文、数据更新关系，以及是否允许阻塞或重入。
- 解释“为何需要这样做”，不逐行翻译代码。明显的赋值、循环不写冗余注释。
- `TODO` 必须指出具体缺失信息或动作，不用 TODO 代替功能完成或实际验证。
- 实现变化时同步修订对应注释；文档更新也需包含在批准清单中。

正确：`/* 先限幅再积分，避免输出饱和期间积分继续增长；限值来自模块配置。 */`

不采用：`/* 设置数值 */`、`/* 已验证安全 */`（没有对应验证证据）。

## 6. 人工审阅项目

检查模块命名和职责是否一致，单位与转换是否正确，参数来源是否可靠，接口是否完整，
错误和并发行为是否明确，注释是否解释设计。脚本通过不能替代这些判断。
保护策略和硬件行为的具体设计属于后续开发任务，本轮规范不预设数值。
