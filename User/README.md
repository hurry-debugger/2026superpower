# 自维护固件目录

本轮只有此说明文件，未创建业务模块，也未接入 Keil 构建。
新增代码前必须先阅读根目录 `AGENTS.md` 与 `docs/coding_style.md`，在对话中提交逐文件修改清单，
获得用户同意后再创建目录、代码或修改构建配置。

## 规划

```text
User/
├── App/          # 应用状态、任务编排、保护策略与业务协作
├── Bsp/          # 板级采样、输出、外设访问和字节收发
├── Algorithm/    # 不依赖硬件的算法
└── Config/       # 有明确单位、来源和适用范围的配置
```

以上四个子目录是后续规划，按实际模块需要并获批后再创建；不预先堆放空实现。
C/H 在模块目录中配对存放，文件名小写下划线。新模块可以从 `templates/module_template.c/.h`
提炼结构，但必须替换模块名称并完成真实契约，不保留无意义字段或占位参数。

App 可依赖 Bsp、Algorithm 和 Config；Bsp 不反向包含 App；Algorithm 不依赖 HAL。
更复杂的协议或控制拆分在后续方案中明确，不把旧工程目录原样复制进来。

## 与生成工程的边界

**禁止直接编辑 `.ioc`、`Core/` 及其他 CubeMX 生成代码，包括 `USER CODE` 区域。**
放在 User 中的文件也必须确认是自维护来源，不能通过移动生成代码规避保护。
启动、回调、链接和构建接入必须先提出符合该限制的方案并获批。
本目录说明不授权向 `main.c` 添加初始化调用，也不授权改写 Keil 工程。
